CI/CD Pipelines

The GitHub Actions workflows, what triggers them, and the secrets they need.

Framework: Java 25 · Selenium 4.44 · Cucumber 7 · TestNG 7 · Updated 23 Jul 2026

1. The workflows

2. Anatomy of a run (staging-tests)

checkout → setup JDK 25 (Temurin, maven cache) → install google-chrome-stable
        → mvn -B test -Denv=staging -Dbrowser=chrome -Dheadless=true
                      -Dchrome.no.sandbox=true -Dstaging.password=***
        → mvn allure:report (always)
        → upload allure-report artifact (always, 30-day retention)
        → email summary + report link (if SMTP_* set)

No tag filter in CI — on purpose testng.xml's two runners own disjoint tags, so a bare mvn test runs every scenario exactly once. Passing -Dcucumber.filter.tags forces the filter onto both runners and double-executes matches → duplicate OTP requests → a 90-second cooldown. The workflow comment says this explicitly; do not add a tag filter.

3. Concurrency and scheduling

  • Staging uses a concurrency group keyed on the ref with cancel-in-progress, so a fresh push supersedes an in-flight run — two runs must not hit the same login number and trip the OTP cooldown.
  • Nightlies are staggered (staging 20:30 UTC, production 22:30 UTC) for the same reason.
  • Staging PRs skip when only non-test assets change (paths-ignore: dashboard/, docs/, grafana-dashboards/, **/*.md).

5. The Cloudflare reality

ISSUE-001 GitHub-hosted runners live outside India and trip Cloudflare's "verify you are human" challenge on staging; local and Docker runs from India do not. Post-handover, a red CI on Cloudflare grounds is expected — the mandate is coverage, verifiable locally/Docker, not a permanently-green hosted pipeline. The browser-side bypass header is wired; the Cloudflare-side rule (disable Bot Fight Mode / broaden the WAF skip) is an infra task.

6. The report as the deliverable

Every run uploads the Allure report as an artifact (30-day retention) and can email a summary + link. Link mode is used in CI to dodge corporate .zip-attachment filters. test-pipeline.yml additionally publishes to GitHub Pages for click-only stakeholder access.
