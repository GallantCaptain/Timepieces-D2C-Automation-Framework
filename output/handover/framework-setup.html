2. Clone and open

git clone https://github.com/TimepiecesTech/qa-automation.git
cd qa-automation

Re-clone, don't pull The git history was rewritten (a leaked Zephyr token was scrubbed — see the Release Notes guide). Any clone taken before that rewrite is invalid; always start from a fresh clone.

3. JDK 25 and the Maven wrapper

Point JAVA_HOME at a JDK 25 install, then always invoke Maven through the wrapper so the build is reproducible:

# Windows PowerShell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-25"
.\mvnw.cmd -v

# macOS / Linux
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
./mvnw -v

4. Secrets: .env and local property overrides

Nothing secret lives in source control. There are two places real values go, both gitignored:

a. .env at the repo root

Copy the template and fill in what you actually need (email reporting, DB metrics, Cloudflare bypass, staging gate):

cp .env.example .env      # then edit .env

.env.example is placeholder-only and stays committed; .env is ignored (*.env in .gitignore).

b. <env>.local.properties on the classpath

ConfigReader layers an optional src/test/resources/config/<env>.local.properties on top of the committed base config. This is where a developer keeps machine-specific secrets — the staging gate password, or the pilot phone number for account tests — without touching committed files:

# src/test/resources/config/staging.local.properties  (gitignored)
staging.password=CHANGE_ME
pilot.phone=NNNNNNNNNN

Never commit real values pilot.phone and staging.password are intentionally blank/absent in the committed files. The previous owner's real number was hardcoded once and had to be scrubbed at offboarding — do not reintroduce that pattern. See the Configuration (Properties) Reader guide for the full precedence rules.

5. First compile and smoke check

# compile only, offline, no tests — fastest confidence check
.\mvnw.cmd -q -o test-compile

# a tiny live run: the smoke tag against production (no login, no staging gate)
.\mvnw.cmd test "-Denv=production" "-Dcucumber.filter.tags=@Smoke and not @StagOnly"

A green compile plus a passing smoke scenario confirms the toolchain. Full-suite and per-area commands live in the How-To-Run guide.

Dashboardcd dashboard && ...The React trends dashboard. See the Dashboard Setup guide.

Profiles matter Healenium, Grid and ZAP each sit behind a Compose profile. A plain docker compose up starts only the metrics DB and Allure service. This is deliberate — a service with no profile starts with everything, which once broke the Grid command (ISSUE-021).

7. Common setup problems

SymptomCause / fix
invalid target release: 25JAVA_HOME points at an older JDK. Install/point at JDK 25.
Cloudflare "verify you are human" on stagingGitHub-hosted runners outside India trip Cloudflare; local runs from India are fine. Set CF_BYPASS_TOKEN, or run against production. See Known Issues ISSUE-001.
Connection to localhost:5432 refusedThe metrics Postgres is not up. Harmless — the run still passes. Start it with docker compose up -d postgres-dev to silence it.
A staging password prompt on a production runYou are actually on staging. Confirm -Denv is honoured (ISSUE-020 fixed this; the CLI now wins over the suite XML).
