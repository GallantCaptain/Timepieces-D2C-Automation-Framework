Healenium — Self-Healing Locators

What self-healing does, why it is off by default, and how to turn it on safely.

Framework: Java 25 · Selenium 4.44 · Cucumber 7 · TestNG 7 · Updated 23 Jul 2026

1. What Healenium does

Healenium wraps the WebDriver so that when a locator stops matching (the app changed an attribute), it can recover the element from previously-observed node attributes and log a healing event, instead of failing outright. It is a resilience net for locator drift — not a licence to write weak locators.

2. Off by default — and why (DEC-0010 / ADR-0010)

Opt-in twice over Healing is disabled unless both are true:

docker compose --profile healenium up -d     # 1) the backend is running
.\mvnw.cmd test -Dhealenium.enabled=true      # 2) the framework is told to use it

With healenium.enabled=false (the default), DriverFactory returns the raw WebDriver untouched — byte-identical behaviour to not having Healenium at all.

It is off by default because a self-healing net can mask a real regression: a locator that "heals" is a locator the app broke, and you want to know about that during active development rather than have it silently paper over the change.

3. Configuration (src/test/resources/healenium.properties)

KeyValueMeaning
hlm.server.urlhttp://localhost:7878The hlm-backend REST endpoint (must match the compose port mapping).
recovery-tries5How many candidate elements Healenium tries when healing.
score-cap0.6Minimum similarity score to accept a healed match (below this it fails rather than guess).
imitate-hoverfalseWhether to simulate hover during healing.
select-node-attributeid,name,type,value,textWhich attributes fingerprint a node for later recovery.

Read directly These values are read by the Healenium client itself, not through ConfigReader. The healenium.server.url key in the env properties files is a reference copy only.

4. The backend stack

  • hlm-backend — the REST service SelfHealingDriver talks to.
  • healenium-postgres (postgres:13) — its own database, separate from the metrics DB.

Image tag caveat healenium/hlm-backend:latest does not currently resolve on Docker Hub. Because Healenium is off by default this is inert — but whoever opts in must first pin a tag that exists. This is also why both services now sit behind the healenium profile (ISSUE-021): an unresolvable image must never be pulled by an unrelated command.

5. How the driver is wrapped

// DriverFactory.wrapWithHealenium(...)
// healenium.enabled=false → log and return the raw WebDriver (default path)
// healenium.enabled=true  → return new SelfHealingDriver(raw), pointed at hlm.server.url

6. When to actually use it

SituationHealing?
Active development / building coverageOff. You want breakages visible.
A large, stable suite against a rapidly-restyled appConsider on — to ride out cosmetic churn while you catch up.
Debugging a specific flaky locatorOff. Fix the locator (see the Locator Strategies guide).
