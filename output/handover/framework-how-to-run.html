Automation Framework — How-To-Run Guide

The commands that actually run the suite, locally, in Docker and in CI.

Framework: Java 25 · Selenium 4.44 · Cucumber 7 · TestNG 7 · Updated 23 Jul 2026

Companion This is the narrative guide. The one-page command reference lives at output/cheatsheet/Timepieces_Test_Execution_Cheatsheet.html — keep it open beside this.

1. The mental model

Every run is the same Maven command with a few -D flags that answer four questions:

QuestionFlagValuesDefault
Which environment?-Denvstaging · productionstaging
Which browser?-Dbrowserchrome · firefox · edge · brave · safarichrome
Headed or headless?-Dheadlesstrue · falsetrue
Which scenarios?-Dcucumber.filter.tags or -Dsurefire.suitetag expr / a testng-*.xmltestng.xml

Windows quoting In PowerShell, wrap any flag whose value contains a space or an @ in quotes: "-Dcucumber.filter.tags=@Smoke and not @StagOnly". Unquoted, PowerShell splits on the space and the tag expression breaks.

2. The default suite

testng.xml is the default (set in pom.xml as surefire.suite). It runs both BDD runners plus every TDD class, and the two BDD runners own disjoint tags:

  • SmokeRunner — @Smoke and not @Regression
  • RegressionRunner — @Regression or @AuthGated
# the whole suite, headless, against production, skipping staging-gate-only tests
.\mvnw.cmd clean test "-Denv=production" "-Dcucumber.filter.tags=not @StagOnly"

Do not add a tag filter in CI A tag override is applied to both runners, so a scenario matching it runs twice → duplicate OTP requests → a 90-second "too many attempts" cooldown. The staging CI job passes no tag filter for exactly this reason.

3. Everyday recipes

# One area, headed, so you can watch it (also what video recording needs)
.\mvnw.cmd test "-Denv=staging" "-Dbrowser=chrome" "-Dheadless=false" `
  "-Dcucumber.filter.tags=@Accessories"

# A specific convenience suite (isolated TestNG XML)
.\mvnw.cmd test "-Dsurefire.suite=testng-search-api.xml"

# By profile (groups + tags baked in)
.\mvnw.cmd test -PSmokeSuite         # groups=smoke,            tags=@Smoke
.\mvnw.cmd test -PRegressionSuite    # groups=smoke,regression, tags=@Smoke or @Regression

# Environment-scoped tags
.\mvnw.cmd test "-Denv=production" "-Dcucumber.filter.tags=not @StagOnly"
.\mvnw.cmd test "-Denv=staging"    "-Dcucumber.filter.tags=not @ProdOnly"

# Tune parallelism (data-provider threads)
.\mvnw.cmd test "-Ddataproviderthreadcount=4"   # more browsers at once
.\mvnw.cmd test "-Ddataproviderthreadcount=1"   # serialise for debugging

4. The report

.\mvnw.cmd allure:report     # static HTML at target/site/allure-maven-plugin/
.\mvnw.cmd allure:serve      # generate + open on an ephemeral port
py scripts/email_allure_report.py   # emails a summary + link (needs SMTP_* + MAIL_TO)

Video Recording is enabled but only engages when it can capture something real — a headed local run (-Dheadless=false) or Docker (Xvfb virtual display). Headless runs skip video with a loud warning and still capture failure screenshots. See ScreenRecorderUtil.canRecordMeaningfully().

5. Docker and Grid

# Headed-equivalent run inside a container (Xvfb display → real video)
docker compose up -d postgres-dev
./scripts/run-docker-headed.ps1        # wraps the container mvn invocation

# Cross-browser on the self-hosted Grid
docker compose --profile grid up -d
.\mvnw.cmd test "-Dsurefire.suite=testng-crossbrowser.xml" "-Dexecution.mode=GRID" "-Denv=production"

Details in the Docker, Selenium Grid and Cross-Browser guides.
